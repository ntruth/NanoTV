# 拾光 Luma · 产品设计文档

> 版本：2.0 ｜ 平台：macOS 14+ ｜ 文档定位：产品决策与边界，不含实现细节

---

## 1. 一句话与一段话

**一句话**：拾光是一款本地优先的 macOS 照片与媒体库，把「自己的图库」「系统照片」「网络存储与影视源」收进同一个安静的窗口。

**一段话**：照片散落在硬盘、系统「照片」、网盘和 NAS 里，想看全要开四个 App。拾光不要求你搬家——它直接打开你已经有的库，用同一套浏览、检索与观看方式把它们串起来；数据默认只留在这台 Mac 上，能力按需拾起。

## 2. 品牌叙事

- **拾**，是拾起；**光**，是光影；**拾光**，也是时光。
- 每一张照片都是一束被留下的光；拾光做的不是「管理文件」，而是把散落的光一片一片捡回来。
- 品牌视觉由此展开：暖到冷的光谱（历史 → 此刻 → 未来）、环绕徽标的光点年轮、引导页底部那条贯穿三段时光的光线。
- 文案口径统一：讲「拾起 / 放下」而不是「开启 / 关闭」；讲「光」而不是「数据」。

## 3. 目标用户

| 人群 | 典型处境 | 拾光提供的价值 |
| --- | --- | --- |
| 个人摄影爱好者 | 照片分散在本地目录、移动硬盘、系统「照片」 | 一个窗口浏览全部；不迁移、不改原库 |
| 家庭资料保管者 | 十几年照片 + 网盘备份，怕丢、怕乱 | 图库保险库校验与恢复、查重、批量整理、关键词与场景检索 |
| 影音收藏者 | 网盘 / NAS 有大量影片，另有直播与影视源 | 网络存储、网络影院、网络电视共用一套播放器与继续观看 |
| 隐私敏感用户 | 不接受上传与账号体系 | 全本地、端侧识别、可选云端助手自带 Key |

## 4. 设计原则

1. **本地优先**：默认零上传、零账号；任何联网能力都必须可解释、可关闭。
2. **不迁库**：接入系统「照片」图库时只读解析，补充数据写在库内旁挂数据库；用户随时可以回到 Apple 生态。
3. **一屏可达**：图库层级（年 / 月 / 所有照片）与常用入口不藏在二级菜单；键盘优先，鼠标可选。
4. **能力可选**：五个模块可独立拾起；关闭只隐藏入口与搜索结果，不删除已有数据。
5. **慢的可解释**：大图库允许等待，但要显示进度与原因；不允许静默丢结果。

## 5. 信息架构

```
侧边栏
├── 图库（当前图库）
│   ├── 图库总览（导航页：资源 / 照片 / 收藏）
│   ├── 精选集（回忆 / 旅行）
│   ├── 固定（个人收藏 / 人物 / 地图 / 位置 / 视频 …）
│   ├── 媒体类型（视频 / 自拍 / 实况 / 人像 / 全景 / 慢动作 / 截屏 / 录屏 / 动图 / RAW）
│   ├── 更多项目（图库体检 / 整理 / 值得重看 / 重复项 / 关键词 / 包含文字 / 最近…）
│   ├── 场景
│   └── 相簿（全部相簿 / 文件夹 / 智能相簿）
├── 网络存储（每个挂载一行 → 目录树 / 影院 / 媒体类型 / 更多 / 场景 / 相簿）
├── 网络资源（每个资源站一行 → 海报墙 / 分类 / 详情 / 演员）
├── 网络影院（影视源聚合 → 电影 / 电视剧 / 类型 / 日历 / 足迹 / 关注）
└── 网络电视（播放列表 → 频道墙 / 节目单 / 回看）
```

**三个横切入口**：

- **统一搜索**（`⌘F`）：覆盖六个来源，按来源 → 类型分组；返回上一页不重新检索。
- **查看器 / 播放器**：所有来源的照片与视频共用；左侧来源、右侧播放，翻页与序号跟随进入时的列表。
- **来源任务条**：扫描、检索、导入、转码等长任务统一进度与取消。

## 6. 模块边界

| 模块 | 入口 | 数据归属 | 关闭后 |
| --- | --- | --- | --- |
| 图库 | 图库分区 | 当前图库的 SQLite 与媒体文件 | 不可关闭（内容基础） |
| 网络存储 | 网络存储分区 | 每个挂载的凭据、索引与缓存 | 隐藏入口，搜索结果不再出现网盘条目 |
| 网络资源 | 网络资源分区 | 资源站定义与海报缓存 | 隐藏入口与结果；站点定义保留 |
| 网络影院 | 网络影院分区 | 复用影视源与 TMDB 补全缓存 | 隐藏入口与结果；不影响网盘影片 |
| 网络电视 | 网络电视分区 | 播放列表、EPG 与回看缓存 | 隐藏入口并停止拉流 |

> 关键取舍：**网盘里的影片不属于「网络影院」**。影院负责影视源聚合（苹果 CMS / FoFo / 爱看 / 爱壹帆），网盘影片随「网络存储」出现。同名源不会在两个分区重复列两次。

## 7. 核心流程

### 7.1 首次建库

1. 品牌首屏：外观三档弧（浅色 / 深色 / 自动）与 11 个强调色光点环绕「拾光」徽标，点选即全局预览。
2. 第二步：选择要拾起的能力（五个模块）+ 迁移旧照片 + 缓存空间档位（省空间 / 均衡 / 大空间）。
3. 选择位置并创建，写入当前图库的数据库与旁挂设置。

### 7.2 接入系统「照片」图库

打开 `.photoslibrary` → 只读连接 `Photos.sqlite`（必要时建轻量索引）→ 载入相簿 / 文件夹 / 人物元数据 → 照片按窗口分页读取。收藏、隐藏、关键词与查看时间写拾光 sidecar；相簿的增删改经 PhotoKit 写回。

### 7.3 切换图库

每个图库拥有独立照片、相簿、图库级设置、系统库连接、网盘挂载、主题（外观 + 强调色）与助手对话。切换即整套上下文切换，不做两个库并排混排。

### 7.4 统一搜索

输入关键词 → 防抖 → 六个来源并发检索 → 结果按来源流式出现。图库来源命中文件名、标题、相簿 / 文件夹、官方关键词、端侧场景标签与 OCR 文本；点击结果若属于其它图库，先切换 / 连接目标库，再在**原查看器**中打开。

### 7.5 观看

网盘 / 影院 / 电视 / 图库视频统一进入播放器：窗口内或全屏，胶片条、字幕、音轨、倍速、HDR 与刷新率匹配由播放内核负责；离开后回到原来的列表位置。

## 8. 状态模型（产品视角）

- **内容**：照片 / 视频 / 相簿 / 文件夹 / 人物 / 场景 / 地点 / 关键词 / 影视条目 / 频道 / 节目。
- **来源**：图库、系统图库连接、网盘挂载、资源站、影视源、电视源；统一由「源 → 内容 → 播放目标」契约表达。
- **检索**：每个来源产出一个结果分区（命中列表 + 各类型计数），不做全局条数截断。
- **任务**：所有长任务进任务中心，可取消、可回溯，失败给原因。

## 9. 端侧智能的产品定义

- **可选**：识别、聚类、相似检索均可按需运行；未分析时相关分类显示 0，而不是假装有结果。
- **可解释**：场景 / 关键词给出命中来源（标签、OCR、关键词）；美化建议给出理由。
- **可关闭**：不上传原图；云端助手必须自带 Key，31 个写工具执行前逐项确认。

## 10. 质量目标

| 维度 | 目标 |
| --- | --- |
| 启动 | 有图库时直接进入；大库先出骨架与最新一页，后台补全 |
| 滚动 | 百万级图库不掉帧；范围 / 筛选 / 排序下推 SQLite |
| 搜索 | 结果完整优先；单来源慢不阻塞其它来源；同一关键词返回不重跑 |
| 稳定性 | 外置盘拔出、图库被移动、库损坏都给出可操作提示 |
| 隐私 | 默认零网络请求；可审计的联网清单 |

## 11. 路线

- **近期**：统一搜索的索引加速（FTS）、图库导航页的时间线密度、播放器章节与缩略图预览。
- **中期**：iOS 端只读伴侣、图库间选择性同步、记忆影片模板。
- **长期**：可插拔的内容源协议（第三方实现）、跨设备端侧检索。

## 12. 术语

| 术语 | 含义 |
| --- | --- |
| 图库 | 一个 `.photoslibrary` 包，含媒体、数据库与拾光旁挂数据 |
| 源 | 可产生内容的对象：图库、挂载、资源站、影视源、电视源 |
| 播放目标 | 内容 + 播放方式的组合，由播放内核解析 |
| sidecar | 写在图库第一层 `database/` 里的拾光自有数据库 |
| 窗口 | 分页浏览时一次性载入的照片片段（默认 600 张） |
