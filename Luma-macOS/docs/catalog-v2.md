# 网络资源 2.0 · 发现与展示方案

> 范围：`网络资源` 分区（源总览 + 频道页 + 详情页）。目标是把「接入站点」升级成能发现、能追更、能回看的入口。
> 状态：本轮已落地的标记为「已完成」，受站点能力限制或需要更大改动的标记为「后续 / 待做」。
> 最后更新：2026-11-21

## 1. 总览页（卡片墙升级）

- 已完成 · 悬停预览：卡片悬停 0.7 秒后静音循环播放真实流（HLS 走站点要求的请求头），移开立即卸载解码器。
- 已完成 · 源状态徽章：在线 / 需验证（WAF、PoW 未通过）/ 离线 / 检测中 / 未启用；进入总览自动检测，可右键「检测状态」重测。
- 已完成 · 置顶与排序：右键源卡片「置顶 / 取消置顶」，置顶源排在卡片墙最前并显示图钉。

### 10.1 追更闭环：从「条目」升级到「系列」

- 放弃 · 系列归一化：站点标题里的「第 12 集」「EP12」「S01E02」「【中字】」会被拆成十几条，但实测跨源标题格式混乱、归一化误判率高，收益不足以抵消维护成本，不做。
- 放弃 · 日历双粒度：热力格数字虚高的问题随「单日分页 + 展开更多」已缓解，不再引入「系列 / 条目」两套统计口径，不做。
- 放弃 · Up Next 轨道：现有「足迹 → 接着看」已经覆盖续播需求，单独再造一条「接下来看」轨道意义不大，不做。
- 待做 · 系列订阅：把「关注分类」的能力扩展到「追这个系列」，新条目出现时给侧栏与卡片打红点（复用现有 `hasNewContent` / `recordTopItem` 链路）。
- 为什么：Trakt 的 Up Next + 日历、Jellyfin 的 Upcoming、Netflix 的 Continue Watching 都是同一件事——用户回来第一眼要知道「我追的东西更新了没有、下一集是哪集」。我们现在只有「继续观看」的续播，没有「接下来」。（Up Next 已放弃，仅保留系列订阅。）

### 10.2 降噪与筛选

- 已完成 · 状态角标：海报左上角依次挂「未看 / 看至 N% / 已看」「稍后看」，右下角挂「刚上架 / 更新中」；已看条目封面压暗并隐藏满格进度条，排行榜前三同步显示「已看」。
- 放弃 · 未看优先：顶栏筛选会把条件藏进菜单，实际使用频率很低；状态角标已经能直接读出未看 / 看至 N% / 已看，不再单独做筛选菜单。
- 放弃 · 隐藏已看：已看条目已经压暗并打勾，信息足够；再加「一键隐藏」会让列表状态难以预期，不做。
- 结论：本节两项均已放弃，只保留已完成的状态角标。

### 10.3 推荐与策展

- 待做 · 条件式智能集合：聚合片单目前只有关键字。加结构化条件行（源多选、年份区间、时长区间、是否中文字幕、分类），卡片上把条件显示成胶囊——这是 Plex Smart Collections / Jellyfin smart playlist 的核心用法。
- 为什么：Plex Discover 靠「统一清单 + 推荐」把用户留在应用内，Hulu 靠人工策展 + 算法重排提升发现率。我们的优势是本地有真实观看行为，不需要账号体系就能做内容相关推荐。

### 10.4 搜索

## 精选合集（91porna 三级实体）

- 索引页：顶部一条「精选合集 · 当前分类 · N 个合集」说明条；每个合集卡片带「合集」角标，底部保留「N 部」，和普通视频卡片区分。
- 合集详情：先按标题里的「共 N 部」估算需要的翻页数，只翻必要的页；跨页去重后重新编号，保证「第 N 部」连续。
- 加载不全时显示「已加载 x / N 部」并提供「重新解析」按钮；正常加载完成不显示这一行。
- 进度：标题行显示「已看 x 部」与「看到：某个视频」；已看过的卡片压暗并打勾，当前播放的部用强调色描边。

## 内部结构

  - 新条目 / 新封面 URL：没有对应文件才下载一次，之后永远读本地。
  - 历史未变（URL 相同）：从磁盘直接读，全程不请求网络。
