# 拾光 Luma 1.2.1 发行说明

- **版本**：`1.2.1`（Build 7）
- **对比基线**：`d09a272`（拾光 Luma 2.0 基线）
- **变更规模**：本次提交 256 个文件（+71,103 / −29,261 行），其中新增 Swift 文件 99 个（56,752 行）
- **适用系统**：macOS 14 Sonoma 及以上（Apple Silicon / Intel）
- **发行形态**：`Luma.app` 免安装包 + `Luma-1.2.1-macOS.zip`

---

## 0. 一句话总结

1.2.1 是「多形态收口」版本：把图库、网络存储、网络影院、网络资源、网络电视从五套各自为战的实现，收敛到同一套状态组件、任务中心、请求会话、错误恢复、播放 OSD 与入库入口；同时把网络影院补成「多源聚合 + 可换源」，把网络电视补成「可追、可录、可提醒」。

---

## 1. 汇总

### 1.1 产品角度

- **五种形态一套体验**：空态、骨架、失败态、恢复入口、任务进度、播放控制全部统一，用户在不同模块之间切换不再需要重新学习一遍交互。
- **网络影院从「能看」到「好用」**：同一部片在多个影视源上不再二选一，详情页直接列出「N 个源」并可换源播放；补上稍后看与来源健康提示。
- **网络电视从「能播」到「能管」**：赛事支持多台同播切换；新增录制中心（定时录制 / 立即录制 / 追剧录 / 录制列表）；新增球队与联赛关注，并能批量为关注赛事排开播提醒。
- **夜航成为电视首页**：赛事、黄金时段、热播综艺、人物记录四个板块共享一次节目单扫描，角度、类型、时段筛选与热度条都在同一页完成。
- **模块开关口径清晰**：「网络影院」是独立开关，关闭只影响网络影视源入口与搜索结果，不会连带隐藏网盘里的影片。
- **本地能力继续加强**：端侧人物聚类、场景、OCR、图库体检、整理工作室、值得重看、足迹回放全部本机完成。
- **专业工具对齐桌面习惯**：评分 / 旗标 / 色标、智能相册、批量更改、导出选项、压缩选项、快捷键与菜单栏命令形成完整闭环。
- **隐私边界明确**：端侧分析不上传照片；AI 默认只发元数据与端侧标签；API Key 与网盘 Cookie 存钥匙串。

### 1.2 技术角度

- **新增能力层**：`LumaContentCore` 增加 `Commands`（命令策略）、`Ingest`（统一入库）、`IPTV`（M3U / 台名 / 省份）、`Content/MetadataEnricher`（详情补全中心）。
- **快照从六套收敛为一套**：网络影院列表快照从 `catalog_kv` 的 JSON 键迁入 `catalog_snapshots` 表，与网络资源共用写入、LRU 淘汰与清理。
- **请求会话统一**：`HTTPSessionProfile`（cloud / artwork / probe / stream）+ `HTTPSessionPool`，9 处 `URLSessionConfiguration.ephemeral` 全部收编，Cookie 语义按画像保留。
- **入库统一**：`IngestService` 成为唯一写入口；4 处直接 `ImportService.importFile` 的旁路全部收口到 `LibraryIngestService.importLocalFile`。
- **AI 工具 provider 化**：`AIToolRegistry` + `AIToolProviders`（影院 / 网络资源 / 网络影院），中央 switch 不再感知各源细节；工具总数 60 个。
- **大文件拆分**：`CinemaLibraryView` 12,064 行 → 17 个文件；`GalleryView` 3,094 → 553 行 + 5 个扩展；`SidebarView`、`CloudStoragesHub`、`CollectionsView`、`CatalogChannelView`、`SearchResultsPage` 同步拆分。
- **查询下推**：`SystemIndex` 拆出 `+DirectQuery` / `+DirectSets` / `+Metadata` / `+Query`，系统图库大列表的筛选、排序、分段下推到 SQLite 与 PhotoKit。
- **状态与进度统一**：单一 `sourceJobHistory` 持久化任务历史，所有模块的进度、取消、归档走同一条时间线。
- **错误模型统一**：`SourceError` + `RecoveryAction` 覆盖网盘、WebDAV、SMB、站点、URL、Cookie 失效，界面只渲染一套错误卡。

### 1.3 功能角度

- 网络影院：多源同片聚合、播放源切换、稍后看、来源健康、5 个 AI 工具、菜单命令接入。
- 网络电视：赛事多台同播、定时录制、立即录制、录制列表、追剧录、关注球队 / 联赛、批量排提醒。
- 底座：网络影院接入统一资料补全、快照统一、入库收口、Cookie 失效进入「重新登录」。
- 图库：视图切换、堆叠、筛选、排序、缩放、批量更改、智能相册、体检、整理工作室、美化推荐、值得重看。
- 播放：字幕（内嵌提取 / 在线搜索 / ASS 样式 / 偏移）、音轨、音频延迟、倍速、画中画、截帧、全屏、片头片尾跳过。
- 网络能力：云盘上传 / 下载 / 重命名 / 新建文件夹、WebDAV / SMB、站点聚合、资源榜单 / 日历 / 足迹 / 关注 / 播放列表。
- AI：60 个工具、跨源检索与播放、相簿与文件夹整理、压缩与美化、修改前确认、对话记录随图库保存。

## 2. 本次 Top 10 亮点

1. 网络影院「一部片多个源」：详情页直接换源，不再丢源。
2. 网络电视赛事「N 台同播」变成可直接切台的下拉。
3. 录制中心：定时录制 + 立即录制 + 追剧录 + 录制列表一站式。
4. 关注球队 / 联赛：自动从赛事标题拆词，一键关注、批量排提醒。
5. 六项统一（空态 / 导航 / 任务中心 / 请求 / 错误恢复 / OSD）全部落地。
6. 网络影院接入统一资料补全（可用线路、TMDB 评分、豆瓣评分）。
7. 快照统一：网络影院与网络资源共用 `catalog_snapshots`。
8. 入库收口：系统库拷贝、剪贴板、美化输出统一走 `IngestService`。
9. Cookie 失效不再只提示「重试」，直接给「重新登录」。
10. 大文件拆分与查询下推，图库 / 影院 / 侧边栏的可维护性与大库性能同步提升。

## 3. P1 · 网络影院

### 3.1 多源同片聚合

- 新增 `NetworkCinemaModel.variants`：主列表仍按「归一化标题 + 电影/剧集」只留一条，但同名影片在其它源上的条目全部留档，不再被合并逻辑丢弃。
- 新增 `NetworkCinemaModel.sources(for:)`：返回同一部片在全部源上的条目，当前条目强制排第一。
- 聚合登记覆盖四条路径：快照恢复、首屏聚合、下滑翻页、跨源搜索。
- 换图库、清缓存时同步清空 `variants`，避免旧库条目串入新库。
- `NetworkCinemaModel.item(refID:)`：按 `sourceUUID|itemID` 反查条目，供详情页与资料补全共用。

### 3.2 播放源切换

- 详情页新增播放源下拉：显示「N 个源」，逐条列出源名与该源健康状态（颜色点 + 文案）。
- 点选某个源：`store.networkCinemaDetail` 切到该源的同一部片，分集、播放、原站入口全部跟随。
- 单源时下拉自动隐藏，不占版面。
- 源不可达时只标记该源健康状态，不阻塞其它源。

### 3.3 详情页动作

- 播放 / 继续播放 / 从第 1 集开始（有观看记录时出现）/ 预告片 / 稍后看 / 打开原站 / 播放源，七个入口统一排在档案卡动作区。
- 稍后看走网络资源同一份数据（`catalog.setFavorite`），两个模块共享同一个清单。
- 「打开原站」优先打开第一集页面，没有分集时退回影视源首页。

### 3.4 AI 工具（新增 5 个）

| 工具 | 说明 |
| --- | --- |
| `list_network_cinema_sources` | 列出已启用且支持网络影院的影视源 |
| `list_network_cinema` | 按分页（电影 / 剧集）列出聚合条目，支持 limit |
| `search_network_cinema` | 跨影视源搜索，返回分组、总数与失败源计数 |
| `network_cinema_history` | 网络影院续看记录：来源 / 条目 / 集数 / 进度 / 最近观看 |
| `play_network_cinema` | 按 ref 播放指定条目，支持 `#N` 与 `sourceID|itemID` 两种引用 |

- 工具总数：图库 33 + 网络资源 9 + 本地影院 13 + 网络影院 5 = **60 个**。
- `AILibraryTools.count` 自动汇总四组定义，新增工具不需要再手改计数。

### 3.5 命令与菜单统一

- `SourceCommand` 新增：`playItem`、`watchlist`、`openSourceSite`。
- `CommandContext` 新增：`canPlayItem`、`canWatchlistItem`、`canOpenSourceSite`，内容命令与照片命令互斥判断。
- 详情页三个按钮改为只读 `CommandPolicy`，不再各拼 `.disabled(...)`。
- App 菜单在「网络影院详情打开」时新增内容条目区：「加入稍后看 / 从稍后看移除」「打开影视源站点」，可用性同样来自 `CommandPolicy`。
- 修复 `CommandPolicy` 新增内容命令后的 switch 穷尽性编译问题，并补上内容命令的兜底分支。

### 3.6 模块开关口径

- 明确 `AppModule.cinema` **只代表网络影院**：关闭后隐藏网络影院入口与搜索结果。
- 网盘 / 本地影片（影院货架、AI 刮削）随「图库」与「网络存储」展示，不受影院开关影响。
- 设置页说明同步更新，避免「关影院把网盘影片一起关掉」的误解。

## 4. P2 · 网络电视

### 4.1 赛事多台同播

- `TVSportEvent` 新增 `channels: [TVChannel]`：同一场赛事的所有同播频道全部保留。
- `mergeSport` 负责按频道 ID 去重、累加同播数、保留频道权重最高的台作为默认打开项。
- 夜航赛事行的「N 台同播」由纯文字改为下拉菜单：显示台号 + 台名，点选即按所选台执行。
- 直播 / 回看 / 开赛提醒三种动作对任意同播台生效；回看跟随该台自己的 `catchup-source`。
- 赛事角度（当前热播 / 即将开赛 / 历史 / 未来）与体育类型筛选保持不变。

### 4.2 录制中心

**模型**

- 新增 `TVRecording`：频道 ID / 台名 / 所属播放列表 / 标题 / 流地址 / 请求头 / 协议 / 开始时间 / 时长 / 状态 / 落库条目 ID / 备注。
- 状态：`scheduled` → `recording` → `finished` / `failed` / `cancelled`；`isPending`、`isExpired`、`end` 为派生属性。

**调度**

- `IPTVBrowserModel` 内置 20 秒一次的录制调度器（主 RunLoop `.common` 模式），换图库后重新加载并启动。
- 到点自动开录；开始时间已过 10 分钟的条目标为「错过了开始时间，未录制」，不在用户打开应用时突然补录一堆旧节目。
- 应用退出时仍在「录制中」的条目，下次启动如实标为「已取消：应用退出，录制已中断」。

**入口**

- 节目回看详情条：新增「录制 / 已排录制」按钮（节目未结束时出现）。
- 赛事行右键菜单：新增「定时录制」与「立即录制 30 秒」。
- 追剧录：对已追节目，一键为「下一场播出」排录制。

**执行与进度**

- 录制统一走 `IngestService` 的 `.remoteClip`（远端直播流 + 固定时长），完成后落进当前图库。
- 开始录制时在统一任务中心登记 `.record` 任务，抓流、完成、失败都有进度与文案。
- 定时录制按节目时长录制，最长 2 小时；立即录制固定 30 秒。

**列表与管理**

- 夜航页新增「录制中心」面板（`TVRecordingsPanel`）：
  - 等待录制 / 录制中 / 已完成 / 失败 / 已取消五种状态与配色；
  - 开始–结束时间、台名、备注（失败原因、中断原因）；
  - 取消（等待中）、移除（已结束）、一键清理已结束；
  - 「追剧录」区：列出已追节目，一键录制下一场。
- 录制数据随图库 SQLite 保存，切库互不串扰。

### 4.3 夜航关注与提醒

- 新增 `TVSportFollow`：关键词 + 类型（球队 / 联赛）+ 创建时间，随图库保存。
- 关键词提取 `followCandidates(in:)`：按 `vs / 对 / — / - / · / | / ： / 空格 / 括号` 等分隔符拆词，过滤「直播 / 重播 / 决赛 / 小组赛 / 常规赛」等泛词，最多返回 4 个候选。
- 赛事行右键菜单可直接关注 / 取消关注候选词；命中关注的赛事行显示金色「关注」徽标。
- 夜航赛事区新增「我的关注」栏：
  - 关注词标签，点击即取消关注；
  - 「为关注赛事排提醒」：扫描当前赛事与未来赛事，为尚未提醒的关注场次批量排系统通知；
  - 提醒复用 `TVReminderCenter`，不新增通知通道。
- 关注只影响高亮、筛选与提醒，不修改节目单。

## 5. P3 · 底座与架构

### 5.1 MetadataEnricher 接入网络影院

- 新增 `NetworkCinemaMetadataEnricher`，`SourceKind = .cinemaFeed`，注册进 `LibraryStore.metadataEnrichers`，与本地影院共用同一个补全中心。
- 补全事实：
  - 「可用线路」：同一部片在几个源上有、前三个源名；
  - 「TMDB 评分」：来自已匹配的 TMDB 补全；
  - 「豆瓣评分」：只读已缓存结果，详情页不额外发请求。
- `NetworkCinemaModel` 新增 `item(refID:)` 与 `cachedDoubanRating(for:)`。
- 详情页资料网格顺序：本地事实 → 源站结构化事实 → 统一补全事实，同名标签自动去重。

### 5.2 快照统一

- `NetworkCinemaSnapshotStore` 从 `catalog_kv` 的自定义 JSON 键迁入 `catalog_snapshots` 表。
- `CatalogDatabase` 新增通用接口：`saveSnapshotData(_:savedAt:forKey:)`、`snapshotData(forKey:)`；`saveSnapshot(_:forKey:)` 改为复用同一路径。
- 网络影院快照 schema 升到 v2：
  - 迁移时清空旧快照；
  - 删除旧 `catalog_kv` 键（`networkCinema.snapshot.v1.*`）；
  - 首次进入重新聚合，属预期行为。
- 网络影院与网络资源现在共用同一张表、同一套 LRU 淘汰与清理入口（`deleteSnapshots(prefix:)` / `pruneSnapshots` / `clearSnapshots`）。

### 5.3 入库收口

- `LibraryIngestService` 新增 `importLocalFile(_:)`（nonisolated），作为单文件入库唯一入口。
- 替换 4 处旁路直调：
  - 系统照片库拷贝（`LibraryStore+SystemLibrary`）
  - 剪贴板粘贴（`LibraryStore+Selection`）
  - 系统图库照片美化输出（`LibraryStore+Beauty`，2 处）
- 视频片段、远端视频、图片数据继续走 `IngestService` 的既有分支，行为不变。
- 批量导入流水线（`runImport`）仍是唯一实现，`IngestService` 的本地文件分支调用它。

### 5.4 Cookie 失效纳入恢复动作

- `SourceErrorMapper` 新增 Cookie / Token 失效文案识别：
  - 登录 / 登陆 / 重新登录 / 授权失效 / 授权过期 / 失效 / 过期；
  - cookie / token / expired / unauthorized / invalid session。
- 命中后映射为 `SourceError(kind: .unauthorized)`，恢复动作给出「重新登录 + 重试」。
- 夸克 31001、115 登录失效等既有映射保持不变。
- 侧边栏源行健康点、错误卡、失败态共用同一份恢复动作。

## 6. 统一体验（六项统一）

### 6.1 空态 / 骨架 / 失败态

- 新增 `LumaStateViews.swift`：`LumaEmptyState`、`LumaEmptyAction`、`LumaLoadingState`、`LumaShimmer`、`LumaSkeletonGrid`、`LumaFailureState`。
- 删除各模块自建实现：`CloudHubEmptyState`、`CinemaShimmer` 等。
- 五个形态的空态图标、标题、说明、动作按钮位置一致；骨架动画时长与亮度一致；失败态统一带恢复动作。

### 6.2 导航状态

- `SourceSidebarRow` 的健康点可点击，弹层复用 `SourceErrorView`。
- 新增 `onRetry` / `onReauthorize` 回调：侧边栏即可完成重试与重新登录。
- 源状态、错误原因、恢复入口不再需要先进入页面才能看到。

### 6.3 任务中心

- 任务历史收敛为单一 `sourceJobHistory`（持久化键 `source_job_history`）。
- 新增 `archiveSourceJob`、`mergedFinishedSourceJobs`、`clearSourceJobHistory`。
- 删除 `CinemaTaskRecord` 与 `TaskTimelineEntry.cinemaTask`，影院任务不再单独成线。
- 修复刮削一次注册两个任务的重复问题。
- 统一进时间线的任务：云盘扫描、站点健康、影视聚合、TMDB 补全、资源搜索、电视连接检测、节目单更新、频道探测、录制、片头识别。

### 6.4 请求配置

- `HTTPSessionProfile` 四档：
  - `cloud`：网盘 API 与下载，保留 Cookie 与登录态；
  - `artwork`：海报 / 台标 / 封面；
  - `probe`：连通性与抓帧探测，不带 Cookie；
  - `stream`：视频流与转封装输入。
- `HTTPSessionPool.shared.session(_:)` 统一发放，避免每处自建会话。
- 收编 9 处：夸克、115、阿里云盘 Cookie 鉴权、`CloudProviders`（3 处）、`CloudSupport`、`WebDAVClient`、`WebDAVResourceLoader`。

### 6.5 错误与恢复入口

- 统一 `SourceError` + `RecoveryAction`：重试 / 重新登录 / 浏览器打开 / 重配来源 / 允许自签证书 / 打开系统设置。
- `SourceErrorView` 与 `LumaFailureState` 共用一套动作渲染。
- 网盘、WebDAV、SMB、资源站点、URL 错误全部经 `SourceErrorMapper` 收敛。
- 新增 Cookie 失效文案识别（见 5.4）。

### 6.6 播放 OSD

- 新增 `TVChannelActionCluster`（`style: .toolbar / .overlay`），电视工具栏与播放 OSD 共用一组频道动作。

## 17. 网络电视（模块）

### 17.1 频道

- 内置三条源：我的 IPTV（国内直连）、IPTV 组织（需代理）、APTV（直播 + 回看）。
- 导入自己的 M3U；内置源只能停用不能删除。
- 同名频道跨源合并，保留多条线路；线路按协议与请求头分别记录。
- 频道排序：央视 1~N → 中央其他 → 凤凰 → 各省（卫视优先）→ 港澳台 / 海外。
- 分组：按类型 / 按省份；快捷筛选：收藏 / 最近。
- 搜索：台名去后缀（「上海电视台」→「上海」），并按省份归属命中本地台。
- 台标：走 `TVLogoCache`（内存 + 磁盘 + 网络），浅色台标自动换深色底板。
- 直播画面：`TVPreviewCache` 缓存抓帧。

### 17.2 节目单（EPG）

- 双 XMLTV 合并：主节目单（jsDelivr 镜像）+ 补充节目单（epg.pw 中国区），按频道去重，覆盖前 3 天 / 后 3 天。
- 源头部 `url-tvg` / `x-tvg-url` 自动读取，也可手动填写。
- 启动先从磁盘垫上次节目单，再后台刷新。
- 节目详情：简介、时长、是否直播、回看入口、预约、录制、追剧。

### 17.3 回看

- 按 `catchup-source` 模板生成回看地址（`${start}` / `${end}` 等占位符）。
- 回看天数：源声明优先，未声明按 3 天收敛。
- 回看走点播模式，显示进度条而不是直播沿。
- 回看不并入直播线路，避免误切回直播。

### 17.4 信号与探测

- 每频道实时抓帧探测：空闲 / 探测中 / 可用 / 不可用。
- 探测并发 2 路，结果进任务中心，可停止。
- 探测报告：分辨率、编码、码率、延迟、抓帧。
- 24 小时探测采样与可用率；陈旧信号巡逻。
- 线路偏好：可锁定某条线路为默认；锁定失效时自动回退最佳线路。
- 播放失败自动顺延到下一条线路，逐条记录失败原因。

### 17.5 夜航

- 四个板块：最近赛事、黄金时段、热播综艺、人物记录。
- 赛事四个角度 + 体育类型筛选；同播合并与多台切换。
- 黄金时段 19:30–23:30：类型筛选、30 分钟热力条、时段筛选、跨台同播合并。
- 综艺 / 人物货架：同节目跨台只留一条。
- 页头：刷新节目单、推荐规则说明。
- 新增：我的关注、录制中心。

### 17.6 预约与追剧

- 单节目预约：开播前系统通知。
- 追剧 / 追赛：按归一化节目名订阅，跨频道、跨天命中。
- 追剧日历：未来 7 天命中的播出，按时间排序。
- 订阅自动为最近 3 次播出排提醒，避免一次塞满通知。
- 追剧录：给订阅的下一场播出排录制。

| `CatalogChannelView` | 1,807 | 拆分 + `CatalogChannelComponents` |

### 22.2 缓存与查询

- 图片：`ArtworkCache`（actor）+ `MemoryImageCache` 本地解码内存池。
- 台标 / 直播画面 / 影院海报 / 资源封面统一到同一套图片缓存规则。
- 派生数据缓存：频道聚合、可见频道、EPG 频道键、节目单按天、频道号索引、探测采样节流落盘。
- 系统图库查询下推：筛选 / 排序 / 分段交给 SQLite 与 PhotoKit，只取窗口页。
- 快照：网络资源与网络影院共用 `catalog_snapshots`，首屏先铺上次内容再后台刷新。

### 22.3 并发与任务

- 导入：最多 6 路并发，哈希闸门避免同批重复。
- 探测：电视 2 路并发；云盘 / 站点按队列串行。
- 任务中心：统一 begin / update / finish / fail / archive / cancel，进度可取消。
- 录制、刮削、补全、搜索、扫描都可在后台继续，切页不中断。

### 22.4 构建

- `build.sh` 默认 release；`PACKAGE=1` 输出 zip；`NOTARIZE=1` 支持公证。
- 内置 ffmpeg / ffprobe；优先打包带 libplacebo 的 ffmpeg-full（杜比视界 Profile 5），缺失时退回静态包。
- 固定本地签名身份，避免 ad-hoc 每次换哈希导致钥匙串反复授权。
- 单文件 ≤ 2,000 行约束继续执行；本轮新增文件均满足。

## 25. 已知限制

- `TVHubView`（6,589 行）、`VideoPlayback`（4,427 行）、`PhotoViewer`（2,848 行）仍超过单文件 2,000 行规范，后续继续拆分。
- 录制依赖源站直播流当前可拉取；长节目录制会占用较长时间与磁盘，应用退出会中断（下次启动如实标记）。
- 关注关键词按标题字符串匹配，标题写法差异较大时可能漏命中或误命中，可在关注栏直接取消。
- 播放源切换依赖详情页成功取到对应源的分集；源站不可达时只展示该源健康状态，不阻塞其它源。
- 百度底图需要自备 AK；高德与苹果底图无需 AK。
- 图形字幕（PGS）只能识别不能提取为文本；杜比视界 Profile 5 需要随包 ffmpeg-full。
- 系统图库写入受系统权限与 PhotoKit 能力限制，部分操作需要用户授权。
